Group-scoped memories never reach a private chat, not even the owner's. Facts and episodes from a group get `Scope::Group { id }` (src/mind/reflect.rs), and `Scope::permits` (src/ns.rs:122) admits them only when the audience is that same group. So the owner cannot talk with him in DM about what happened in a group. The privacy test `private_secret_is_withheld_from_groups` (src/social/privacy.rs) asserts this explicitly. Person records themselves are merged by id (owner = `owner` across platforms), so this is a scope problem, not an identity one.

Direction: allowed flow is group -> its members in private; never private -> group. The blocker is that we don't know a group's membership (ns.rs:120). Group-member analysis first:
1. Track membership per group: who has been seen speaking there (from envelopes / episode participants), and optionally the platform's member list (NapCat get_group_member_list) for an authoritative set. Membership is append-only (see owner decisions).
2. Widen `Scope::Group { id }` to permit a private audience whose members are all known members of that group.
3. Interim/minimal option: permit only the owner. Caveat: #47 collects read-only groups the owner may not be in, so even owner-only needs "owner is a member of that group" to be strictly correct.

Owner decisions (2026-11-03): a member who joined later may see group memories from before they joined. A member who left keeps access. So membership is simply "ever seen in the group", append-only; no join/leave time checks are needed.

Acceptance: membership store + tests; permits tests for member / non-member / owner DMs; flip the last assertion in the privacy test and add a non-member-DM test that still withholds.

Boundary: changing `Scope::permits` is a privacy boundary (L4 per DESIGN section 6) and needs the owner's decision before implementation.
