The owner confirmed that A06 requires a master kill switch and judged the backend control design seriously flawed; backend refactoring may be necessary. This is an architectural control/lifecycle task, not a prompt change or a shorter HTTP timeout.

Design and implement a control path that remains responsive while chat/triage/reflection/model requests are stalled. It must handle owner freeze/stop, process shutdown and task deadlines without waiting for the persona event handler. Ordinary conversation ordering may remain serial. Define the exact switch scope across pending/in-flight model calls, delegated child process trees, evolution checking/handoff, media/background work and external dispatch. Cancellation must leave truthful resumable status and must not replay unknown external effects.

Deliver the control/lifecycle design and migration plan before a broad refactor. Separate immediate cancellation/deadline enforcement from persona decisions and long I/O; specify who owns state and how completion/cancellation races are settled. The owner has approved the need for this capability, not a particular actor/thread/process topology.

Acceptance: a synthetic provider holds a request open while owner freeze/stop and a shutdown signal are injected; the control path responds within an explicit short bound and active child trees are stopped without waiting for the 600-second request timeout. Task deadlines fire independently; queued work cannot restart while frozen; late completion does not overwrite canceled state or duplicate sends. Test all active work categories against the agreed switch scope.
