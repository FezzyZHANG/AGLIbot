Before handling an Inbound event, drain events that have already arrived (try_recv) and merge messages from the same chat into one converse() call. Same reasoning as the Super-agent Router batching (long input, short output: 1 -> 40 triggers/min raised batch 1.0 -> 2.8 while latency only went 2.5s -> 3.9s). Merge replies only: if the merged messages ask for several things, the model still marks each task separately (the prototype turns one batch into one ticket, which is a known flaw).

Done when: three owner messages sent while a reply is in flight produce one reply that addresses all three.
