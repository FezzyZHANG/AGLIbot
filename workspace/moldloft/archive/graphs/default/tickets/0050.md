Config is read once at startup, so a change such as adding a group to config/social.yaml `groups` (the reply allowlist) only takes effect after restarting the bot. Add a watcher that notices edits to files under config/ and applies them to the running process without a restart.

Behavior: on change, re-parse and validate the whole file; on success swap in the new value atomically, on failure keep the previous config and log the error (a half-saved or invalid edit must never take the bot down or leave a partial config). Debounce editor save bursts. Log which file reloaded and a summary of what changed (e.g. groups added/removed).

Scope decision needed: which settings are safe to hot-swap (social groups/ignored_groups, floor and reply limits) and which still require a restart (channel connections and tokens, model routing, runtime). Unsafe ones should log 'restart required' rather than apply silently. L4 boundary settings stay owner-edited; the watcher only reads them.
