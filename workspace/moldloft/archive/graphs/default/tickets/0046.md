dotenvy loads .env into AGLI's process environment and every delegate child (codex, dsh) inherits all of it, so Codex research runs on untrusted web content can see BAILIAN_API_KEY, TELEGRAM_BOT_TOKEN, ONEBOT_TOKEN and any future key.

Delegates start from an empty environment plus an allowlist of variables needed to run (PATH, SystemRoot, windir, COMSPEC, PATHEXT, TEMP/TMP, USERPROFILE, HOMEDRIVE/HOMEPATH, HOME, APPDATA, LOCALAPPDATA, ProgramData/ProgramFiles as needed, CODEX_HOME, DSH_HOME, proxy variables). The dsh child additionally receives the owner's dedicated keys from prefixed .env names, renamed: AGLI_DSH_DEEPSEEK_API_KEY -> DEEPSEEK_API_KEY (search), AGLI_DSH_BAILIAN_API_KEY -> the variable the agli profile reads for the model (owner decision in n-agli-q-dsh-tokens / n-agli-q-dsh-search). Codex gets no AGLI keys.

Done when: a test shows a delegate child sees allowlisted variables and the renamed DSH keys only where intended, and does not see TELEGRAM_BOT_TOKEN / BAILIAN_API_KEY / ONEBOT_TOKEN; the live Codex round trip still works.

Owner direction 2026-11-01: implement this through ns management. Secrets are information like any other, so who may receive them is a ProcessingPolicy (src/ns.rs), the same concept that already decides which models/executors may process a memory:
- Each secret variable is registered with a policy: LocalOnly (stays in AGLI's process: TELEGRAM_BOT_TOKEN, ONEBOT_TOKEN, BAILIAN_API_KEY, OWNER ids...) or Providers{names} naming executors (dsh, codex), plus an optional rename for the child (AGLI_DSH_DEEPSEEK_API_KEY -> DEEPSEEK_API_KEY for dsh).
- A delegate's environment = non-secret runtime allowlist (PATH, SystemRoot, ...) + registered secrets whose policy allows that executor. Default deny: unregistered variables that look secret (*KEY*, *TOKEN*, *SECRET*, *PASSWORD*, *COOKIE*) are never passed.
- Registry defaults live in code next to ns.rs; moving it to config/ (L4 boundaries) is the owner's call, with the proposed YAML recorded here.
