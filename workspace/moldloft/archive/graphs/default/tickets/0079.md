Recall today is push-only: code picks episodes/facts for the context with fixed caps, so an old group event the owner asks about in DM may not be retrieved even once #78 lets it through the scope gate.

Idea: let the reply model ask for a recall in-line, e.g. `<回忆>关键词</回忆>`. Code runs one recall (keyword + semantic) with the CURRENT conversation's audience, bound by code and never supplied by the model, appends the results, and re-runs the reply once. Same scope gate as push recall; no MCP and no general tool loop.

Do only after #78 lands and a real miss is observed. Low priority.

Acceptance: intent parsing tests; a test that a pulled recall in a non-member DM still withholds group memories; at most one pull per turn.
