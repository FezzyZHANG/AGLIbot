AGLI's DSH child currently uses the owner's DSH home (~/.dsh), which holds the owner's DeepSeek account login token in .credentials.yaml (deepseek-account-platform/default) next to the owner's own profiles, sessions and storages. DeepSeek search or model plugins might prefer that token over the DEEPSEEK_API_KEY env passed by #46, billing AGLI's runs to the owner's personal login; precedence is unknown.

Give AGLI its own DSH home (default data/dsh-home under the AGLI root, gitignored with data/), passed explicitly as DSH_HOME to the dsh child only, created if missing; the agli profile lives there. The owner's DSH_HOME/USERPROFILE-derived home is never used by AGLI's runs.

Done when: the dsh child's DSH_HOME is the AGLI home regardless of the parent environment; docs/DSH.md tells the owner to create the agli profile there (e.g. `dsh --profile agli --from-default-profile headless` with DSH_HOME set); no credentials file is copied from ~/.dsh.
