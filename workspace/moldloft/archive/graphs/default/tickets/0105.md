The new build refuses the legacy Mongo schema at startup, but ops/deploy.ps1 and DEPLOY.md write the new release pointer and stop the old bot first, so a normal deploy ends with no bot running. migrate-bson --apply has no backup step.

Add a read-only schema preflight before switching. When migration is needed: stop both writers (bot and stickers-web), mongodump, migrate, verify the round trip on a copy, then switch the pointer and check readiness. Also fold in R08 (unknown or retired subcommands such as import-jsonl must exit non-zero instead of starting the bot) and R24 (deploy -Commit 590a346 fails because it always builds the stickers-web bin).
