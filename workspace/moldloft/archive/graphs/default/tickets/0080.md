d85260f added `social.aliases` in config/social.yaml: a group message containing one of these names addresses him like an @ (substring, ASCII case-insensitive, QQ reply quotes skipped). Editing it means editing the runtime's config file.

Goal: one live, owner-managed lexicon in MongoDB, edited in Compass with no file edit and no restart. It holds (1) aliases: names that address him, and (2) group slang (黑话): terms the group uses and what they mean, so he and the floor judge understand them.

## Data
Collection `lexicon` in the bot's database (runtime: `aglibot_xiaozhuang_20261103`), one document per entry:
`{term: "小庄", kind: "alias", scope: null, enabled: true, note: ""}`
`{term: "肉编器", kind: "slang", meaning: "手写汇编/人肉编译的人，调侃", scope: "qq:498701326", enabled: true, note: ""}`
- `_id` is Mongo's default; unique index on (term, scope). `scope` null/missing = every allowlisted group; otherwise one `platform:chat_id` group key.
- `kind`: `alias` or `slang`. `meaning` is required for slang, ignored for alias, capped at 120 chars when used.
- `enabled: false` hides an entry; a missing `enabled` counts as true. Invalid documents (unknown kind, slang with no meaning, empty term) are skipped with one warning per reload, never fatal.

## Behaviour
- Aliases: as `SocialCfg::called_by` today, but from the lexicon and scope-aware (a group-scoped alias only addresses him in that group). Move the matching rules next to the new source rather than duplicating them.
- Slang: for each reply turn in a group, find enabled slang entries (global + that group's) whose term appears in the batch lines (same substring/case rules, quotes included this time since quoted text is still read). Add at most 8, longest term first, as one line inside that turn's `<当前状态>` via the existing `tail(.., notes)` mechanism: `群里的说法：A＝…；B＝…`. Never put them in L1/L2, so the prompt cache stays intact. The same lines go into the floor judge's prompt for that check. Private chats get no slang.
- Privacy: a group-scoped entry never appears outside its group (not in DMs, not in other groups, not in reflection of other namespaces).

## Reload
Re-read the collection at most every 30 s (lazy TTL cache on the group path); standalone mongod has no change streams, so do not depend on them. Log `lexicon reloaded: aliases=+[..]-[..] slang=+N-M` only when it changes. A read failure keeps the last good set and warns once.

## Seed and fallback
- On startup, if the collection is empty and `social.aliases` is non-empty, insert those as global aliases once. After that MongoDB is the only source; keep the yaml field only as that seed and say so in its comment.
- JSONL store (no MONGO_URL): back the same Store method with `data/lexicon.json`.

## Out of scope (later, optional)
Nightly reflection proposing new slang as `enabled: false` entries for the owner to approve in Compass. Not in this ticket.

## Acceptance
- Store tests for both backends: empty, seed-once, enabled=false ignored, invalid docs skipped, TTL refresh picks up an insert, failed reload keeps the previous set.
- agli tests: the existing alias test passes against the lexicon; a group-scoped alias does not address him in another group; slang present in a batch shows up in that turn's `<当前状态>` and the floor prompt, absent slang does not, the cap of 8 holds; a group-scoped slang entry never reaches a DM or another group's turn; L2 is byte-identical with and without slang hits.
- Manual: add a slang entry in Compass; within 30 s a group message using it gets a turn whose log/prompt shows the meaning; add an alias and he answers to it.
